# 問題の原因特定レポート

**日付**: 2025年12月16日  
**問題**: Roll/Pitch RMSEが phase0 (6d4b1bd) から10倍悪化

## 検証結果

| バージョン | Roll RMSE | Pitch RMSE | ジャイロフィルタ |
|-----------|-----------|------------|---------------|
| **6d4b1bd (phase0)** | 0.28° | 0.27° | **なし** ✅ |
| **stash変更後** | 2.51° | 2.65° | **あり (MEX)** ❌ |
| **stash変更後 (MATLAB)** | 2.47° | 2.61° | **あり (MATLAB)** ❌ |
| **現在(6d4b1bd状態)** | 0.28° | 0.27° | **なし** ✅ |

## 結論

### 🔴 問題の根本原因

**`SensorGyroFilter` （ジャイロBiquadフィルタ）の追加が姿勢誤差を10倍悪化させた**

### 原因の詳細

1. **フィルタによる位相遅れ**
   - Biquadローパスフィルタ（カットオフ30Hz）がジャイロ信号に位相遅れを導入
   - 姿勢積分での小さな遅れが累積して大きな誤差に

2. **バイアス推定への悪影響**
   - フィルタリングされた角速度を使用することで、真のバイアス推定が困難に
   - フィルタがバイアスの一部も除去してしまう可能性

3. **高周波成分の過剰な除去**
   - ジャイロの有用な高周波情報（急な姿勢変化）が失われる
   - ESKFの予測ステップで必要な情報が不足

### なぜジャイロフィルタが不要か

1. **ESKFは元々ノイズに強い**
   - プロセスノイズQ、観測ノイズRによる最適推定
   - センサーノイズは既に考慮されている

2. **Biquadフィルタは線形**
   - ESKFの予測モデルは既に線形化されている
   - 追加の線形フィルタは位相遅れを増やすだけ

3. **センサーフュージョンで補正される**
   - 加速度計、磁気計、GPSの更新でジャイロのドリフトは補正される
   - 事前フィルタリングは不要

## 推奨対応

### ✅ 即座に実施すべきこと

1. **`SensorGyroFilter` を無効化または削除**
   ```matlab
   % ESKF.mで以下をコメントアウトまたは削除
   % gyro_config = struct(...);
   % obj.sensor_filters.gyro = SensorGyroFilter(gyro_config);
   % obj.enable_gyro_filter = true;
   ```

2. **predict.mのフィルタ呼び出しを削除**
   ```matlab
   % 以下のブロックを削除
   % if obj.enable_gyro_filter ...
   %     w_meas = obj.sensor_filters.gyro.apply(w_meas, ...);
   % end
   ```

3. **バッチテストで検証**
   - Roll/Pitch RMSE が 0.3° 以下に戻ることを確認

### 📋 Phase 2.1 の正しい結論

**BiquadFilter のC++/MEX移行自体は成功しています：**
- MEX vs MATLAB: 数値的に同等（差異 < 0.05°）
- 実装は正しい
- パフォーマンスも良好

**問題は、フィルタを適用する場所が不適切だった：**
- ❌ ジャイロセンサーの生データに適用 → 姿勢誤差悪化
- ✅ 高周波ノイズ除去が必要な他の用途（例：後処理、可視化）には有効

### 🔄 今後のアクション

1. stash変更を破棄して6d4b1bd状態に戻す
2. `SensorGyroFilter.m`, `BiquadFilter_cpp.m` は残す（他の用途で使える）
3. ESKFでは使用しない
4. Phase 2.2 (AccelFilter) に進む際も同様の注意が必要

## 技術的洞察

### ESKFとセンサーフィルタの関係

**ESKFの設計思想：**
- 生のセンサーデータから最適な状態推定
- プロセスノイズ・観測ノイズモデルで不確実性を扱う
- カルマンゲインで自動的にセンサーフュージョン

**事前フィルタリングが有害な理由：**
1. 情報の損失（高周波成分）
2. 位相遅れの導入
3. ノイズモデルとの不整合

**適切なアプローチ：**
- センサーデータは生のまま使用
- ノイズ特性はR行列で表現
- 外れ値検出は統計的手法（マハラノビス距離など）

### カットオフ周波数と誤差の関係

テストした設定：
- サンプリング: 200 Hz
- カットオフ: 30 Hz (Nyquistの30%)

位相遅れの計算：
```
位相遅れ ≈ atan(ω/ωc) / (2π)
ω = 2π × 5 Hz (運動周波数)
ωc = 2π × 30 Hz (カットオフ)
遅れ ≈ 0.16 / (2π) ≈ 2.6 ms
```

100秒間の累積：
```
累積誤差 ≈ 2.6ms × 角速度 × 時間
角速度 ≈ 0.1 rad/s (典型値)
累積 ≈ 2.6e-3 × 0.1 × 100 = 0.026 rad ≈ 1.5°
```

実測10倍悪化（2.5°）は位相遅れだけでは説明できない
→ バイアス推定への影響も大きい

## まとめ

**BiquadFilter C++移行: ✅ 成功**  
**SensorGyroFilterのESKF統合: ❌ 失敗（設計ミス）**

解決策: ジャイロフィルタを削除し、ESKFは生データで動作させる
