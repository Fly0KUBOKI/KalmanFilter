# C++ コードベース構造

## 最終更新日
2025-12-28

## ディレクトリ構造

```
cpp/
├── Inc/          # インクルードファイル（必須）
│   ├── Common/
│   ├── EKF/
│   ├── ESKF/
│   ├── KF/
│   ├── MEUKF/
│   └── UKF/
├── Src/          # ソースファイル（必須）
│   ├── Common/
│   ├── EKF/
│   ├── ESKF/
│   ├── MEUKF/
│   └── UKF/
├── Lib/          # 独立ライブラリ（必須）
│   ├── Common/
│   ├── Matrix/
│   ├── Quaternion/
│   └── KalmanCore/
├── MEX/          # MEXラッパー（必須）
├── build/        # ビルドスクリプト（必須）
└── bin/          # ビルド出力（必須）
```

## 使用方法

### ビルド

```matlab
cd kalman/cpp/build
build_mex()
```

すべてのMEXファイルが`Inc/`, `Src/`, `Lib/`を使用してビルドされます。

## 他のコンパイル環境での使用

`Inc/`, `Src/`, `Lib/`は他のコンパイル環境でも使用可能です：
- インクルードパス: `-I Inc/`
- ソースファイル: `Src/**/*.cpp`
- ライブラリ: `Lib/**/*.hpp`

## 設計方針

- **型**: `float`型を使用（`double`禁止）
- **整数**: 200以下の整数は`uint8_t`を使用
- **メモリ**: 動的メモリ確保禁止
- **C++標準**: モダンC++機能は使用しない

## ⚠️ 重要な設計原則

### MEXフォルダの役割

**MEXフォルダには実装コードを記述しない**

- `MEX/`フォルダは**ラッパーコードのみ**を含む
- 実装ロジック（アルゴリズム）は全て`Inc/`, `Src/`, `Lib/`に配置
- MEXファイルの役割：
  - MATLABデータ型とC++データ型の変換（ヘルパー関数）
  - `mexFunction`エントリーポイント
  - `Inc/`, `Src/`, `Lib/`の関数呼び出し

### 独立性の確保

**`Inc/`, `Src/`, `Lib/`は他のコンパイル環境でも使用可能**

- `Inc/`, `Src/`, `Lib/`をコンパイルすれば、そのまま他の環境（Arduino、ROS、スタンドアロンC++など）で使用可能
- MEXフォルダに依存しない設計
