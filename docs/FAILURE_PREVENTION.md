# 失敗記録と再発防止ガイド

この文書は、プロジェクト内で発生した重大な失敗事例を記録し、同様の失敗を再発させないための運用ルールとチェックリストをまとめたものです。

（注）過去の具体例として Phase3 のインシデントが含まれますが、本ドキュメントは単一フェーズに限定されません。運用全体のガイドとして継続的に更新してください。

## 概要
- ステータス: 関連修正は実施済み（該当回帰テストの検証済み）
- 関連コミット例: `5e5d6fa`（修正復元）、`409e2c5`（報告ドキュメント追加）

## 発生事象（代表例）
- 発生日時: 2026-01-11（Phase3 インシデント）
- 症状: センサー更新経路が削除され、推定が停止（Max Innovation = 0、Gyro bias = [0,0,0]、Position/Attitude RMSE大幅悪化）
- 実行時間が著しく短くなった（処理欠落の兆候）

## 根本原因（代表例）
- 重要な実装ファイルが削除され、代替として軽量なラッパーのみが残されたため、実際の処理経路（状態書き戻しやMEUKF経路など）が失われた。

## 対応（既に実施済みの流れ）
1. 旧版の実装を復元し、欠落した処理経路を復活させた。
2. 型の不一致や暫定的なインタフェース変更を戻し、ビルド可能な状態に修正した。
3. MEX を再ビルドし、該当する回帰テストを実行して合格を確認した。

## 再発防止策（必須ルール）

**A. 大規模削除前の必須手順**
- 重要ファイル（目安: 500行以上、もしくは機能的に重要）を削除する場合、削除前後で必ず回帰テストを実行し、差分を評価する。

**B. 削除レビュー基準**
1. `diff`/`grep` で内容が完全に重複していることを確認する。ファイル名の一致だけでは不十分。
2. 削除対象の各関数・シンボルが他所に移設済みであることを関数単位で確認する。
3. 削除後にビルドが成功すること。
4. 削除後に回帰テスト（またはライトスモークテスト）が合格すること。

**C. CI と運用ルール**
- PR マージ前に `build_mex()` が成功し、回帰テスト（フルまたはライトスモーク）が通過することを必須化する。
- 大規模削除を含む PR はレビュワーの明示的承認（2人以上推奨）を必須化する。

**D. 監視・早期検出指標**
- Max Innovation が全ステップで 0.0000（継続）→ 即時ロールバック
- Gyro bias が全軸でゼロ（推定停止の疑い）→ アラート
- 実行時間が過去平均の 50% 未満に短縮 → 処理欠落を疑う
- Position RMSE > 10m または Attitude RMSE > 10 deg → ブロック

**E. 開発者チェックリスト（コミット前）**
- [ ] ビルド成功（`build_mex()`）
- [ ] 回帰テスト（`run_batch_10sets()` またはスモークテスト）を実行
- [ ] テスト合格（フル: 10/10 PASS、またはスモーク合格）
- [ ] Position/Attitude の目安を満たすこと（例: Position RMSE < 1.0m、Attitude RMSE < 5.0 deg）
- [ ] Gyro bias が全ゼロでないことを確認
- [ ] Max Innovation が 0 でないことを確認

## 推奨改善（中期的）
- 回帰テストを CI 化し、最低限のライトスモークを PR 段階で自動実行する。フル回帰は夜間バッチ等で実行。
- 削除・統合の影響解析ツール（依存グラフ）を導入し、手作業の見落としを減らす。
- PR テンプレートに「削除対象ファイルの関数一覧」と「削除前後の回帰結果添付」を義務化する。
